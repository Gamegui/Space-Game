## 1. Найденные и исправленные проблемы

### 1.1. 🔴 Устаревший API лидербордов (использовался `ysdk.getLeaderboards()`)

**Документация:** <https://yandex.ru/dev/games/doc/ru/sdk/sdk-leaderboard>
— «Инициализация объекта `lb` с помощью метода `ysdk.getLeaderboards()` **устарела**».
Актуальный вызов: `ysdk.leaderboards.setScore(name, score)`.

**Код:** `src/platform/yandex.ts` `saveHighScore()` вызывал только старый путь.

**Исправление:** переход на `ysdk.leaderboards.setScore()`, старый
`getLeaderboards()` оставлен как fallback для старых сборок SDK.
Попутно из типа убран устаревший `player.getMode()` (документация: «устарел и
позже будет удален из интерфейса»).

### 1.2. 🔴 Двойной вызов `onResume` в полноэкранной рекламе

**Документация:** <https://yandex.ru/dev/games/doc/ru/sdk/sdk-adv>
— `onClose` вызывается «при закрытии рекламы, **после ошибки**, а также, если
реклама не открылась по причине слишком частого вызова».

**Код:** в `showInterstitial()` `onResume()` дёргался и из `onError`, и из
`onClose` — при ошибке колбэк резюма выполнялся дважды. Текущий колбэк
(`handleReturnToMenu → finish`) идемпотентен, поэтому баг был латентным, но
любой неидемпотентный `onResume` в будущем сломался бы. В `showRewarded`
аналогичная защита (`settled`) уже была.

**Исправление:** одноshot-гард `resume()` на все пути завершения.

### 1.3. 🔴 Кулдаун interstitial сжигался впустую

**Код:** `lastInterstitial` проставлялся *до* вызова `showFullscreenAdv`. Если
реклама не показывалась (ошибка, платформенный лимит частоты — «частота вызова
полноэкранного блока управляется платформой»), собственный 3-минутный кулдаун
всё равно считался израсходованным — потерянные показы.

**Исправление:** кулдаун фиксируется в `onOpen` («вызывается при успешном
открытии рекламы»).

### 1.4. 🔴 Не обрабатывались события платформы `game_api_pause` / `game_api_resume`

**Документация:** <https://yandex.ru/dev/games/doc/ru/sdk/sdk-events>
— «Платформа **автоматически показывает полноэкранную рекламу на старте всех
игр**. У стартовой рекламы нет прямых callback-функций — отслеживайте
`game_api_pause`/`game_api_resume`». События также нужны для окна покупки и
переключения вкладок; игры с их поддержкой «могут быть дополнительно
дистрибутированы на внешние площадки». Требования §1.3 (звук при потере фокуса)
и §4.7 (пауза звука и геймплея при полноэкранной рекламе).

**Код:** слушались только `blur`/`visibilitychange`. Частично проблему закрывало
то, что музыка стартует по жесту пользователя (WebAudio), но стартовая реклама,
окно покупки и платформенные показы оставались непокрытыми.

**Исправление:** `yandex.ts` подписывается на события после `init()`
(с guards для старых SDK), добавлены `onPlatformPause/onPlatformResume`.
В `App.tsx` pause зеркалит потерю фокуса (звук + геймплей + клавиши), resume —
консервативный (не снимает пользовательскую паузу автоматически: геймплей
возобновляется только через собственный UI игры, как того требует семантика
GameplayAPI — start не должен вызываться, если игра уже стояла на паузе).

### 1.5. 🔴 Дыры в чек-листе публикации (README)

**Документация:** требования §1.11 (при использовании облачных сохранений в
черновике **включена** опция «Игра использует облачные сохранения») и §1.12
(подключена монетизация); sdk-about (проверка лоадера `IT` через
`?debug-mode=16`); §1.13.6 (паритет списка покупок с консолью).

**Код/доки:** README не упоминал: включение опции облачных сохранений,
подключение монетизации, продукты `premium_pass`/`starter_pack` (код на них
ссылается, но в гайде был только `void_wraith`), проверку лоадера debug-панелью.

**Исправление:** README переписан (10 шагов), PROJECT_HANDOFF дополнен.

### 1.6. 🔴 Устаревшие ссылки на номера требований и URL SDK в доках проекта

**Факт:** требования пере numerated 18.08.2026: `LoadingAPI.ready()` — теперь
**§1.19.2** (в коде/журнале фигурировало «§1.23.2»; §1.23 теперь — запрет
интерактивного ИИ), паритет каталога — **§1.13.6** (было «§1.13»). В
PROJECT_HANDOFF был указан старый загрузчик `https://yandex.ru/games/sdk/v2`.

**Документация:** <https://yandex.ru/dev/games/doc/ru/concepts/requirements>
и <https://yandex.ru/dev/games/doc/ru/sdk/sdk-about> (для хостинга Яндекса —
относительный путь `/sdk.js`; старый лоадер виден в debug-панели как `IF` и не
проходит модерацию).

**Проверено:** сам `index.html` (и в репо, и в zip) уже использует правильный
`<script src="/sdk.js" defer>` — расхождение было только в текстах документации
проекта. Живые комментарии кода и секция конфигурации handoff обновлены
(исторические записи журнала не переписывались).

## 2. Риски и рекомендации — все исправлены (v2.7.11)

### 2.1. ✅ Временный сбой `getPurchases()` на запуске

Было: любая ошибка `getPurchases()` трактовалась как «ничего не куплено» до
перезагрузки. Стало: `getOwnedProducts()` делает одну попытку, при ошибке
повторяет запрос через 1,5 с; если и он не прошёл — возвращает `null`
(«неизвестно»), и App.tsx делает один отложенный фоновый ре-чек через 10 с.
Направление отказа безопасное: неизвестное владение скрывает CTA покупки, но
не может привести к повторной оплате.

### 2.2. ✅ Кратный вызов `getPurchases()`/`getCatalog()` на старте

Было: до 3 вызовов `getPurchases()` + до 3 вызовов `getCatalog()`. Стало:
ровно один `getPurchases()` (`getOwnedProducts()`) и один `getCatalog()`
(`getCatalogOffers()` → `Map<productId, StoreOffer>`); покомпонентные методы
`hasPermanentPurchase`/`getCatalogOffer` удалены.

### 2.3. ✅ Лимиты записи данных игрока теперь защищены в коде

Документация (sdk-player): `setData` — не чаще 100 запросов за 5 минут,
объём ≤ 200 КБ на игрока; `setScore` — 1 раз в секунду. Реализовано в
`yandex.ts`: записи сливаются по ключам в один пакет и отправляются не чаще
одного раза в 5 с (~12 запросов/мин — в 8 раз ниже лимита); критичные записи
(результат забега, покупка, рекорд) уходят немедленно — игрок может закрыть
игру сразу после экрана смерти; пакет больше 180 КБ логируется
предупреждением (платформа отвергает >200 КБ целиком); неудачная запись
возвращается в очередь и ретраится; `setScore` — гард 1 запрос/с с
накоплением максимума. `persistMeta(next, critical=true)` — семантика
текущих вызовов не изменилась (все они редкие и пользовательские).

### 2.4. ✅ Смена игрового аккаунта в диалоге платформы

Подписка на `ACCOUNT_SELECTION_DIALOG_OPENED/CLOSED` (имена из
`ysdk.EVENTS` с fallback на литералы): пока диалог открыт — облачная запись
приостановлена; после закрытия объект `Player` перечитывается, очередь
записей и отложенный рекорд предыдущего игрока сбрасываются (включая гонку
«запись в полёте» — защита через поколение сохранений), и приложение
перезагружает облачное состояние (мета, рекорд, покупки, каталог) под
выбранный аккаунт; при пустом облаке нового аккаунта локальный снапшот
предыдущего игрока не «протекает» — старт свежий.

### 2.5. ✅ `isAvailableMethod` перед `setScore`

`submitScore()` сначала вызывает `ysdk.isAvailableMethod("leaderboards.setScore")`
(документированная проверка доступности для авторизованных) и молча
пропускает отправку для гостей; при отсутствии метода в старых SDK —
прямое поведение как раньше.

### 2.6. ✅ `getPlayer({scopes:false})` — легаси-параметр

Параметр `scopes` отсутствует в актуальной документации; заменён на вызов
`getPlayer()` без аргументов (поведение то же). Устаревший `getMode()` убран
из типов ещё в v2.7.10.

### 2.7. ✅ Флейк локальных тестов (диагноз уточнён при исправлении)

Настоящий источник флаков — `test/cortege_level300.test.mts:158`: тест
ассертил **общее число живых** осколков `< 80`, а инвариант движка — бюджет
**рождения** `MAX_DISCHARGE_SHARDS_PER_FRAME = 40` за кадр; осколки живут до
вылета за экран, и из-за `Math.random` легитимный максимум колеблется (~85),
что и роняло тест рандомно (~20% прогонов). Исправлено: константа
экспортирована из `gameLoop.ts`, порог теста = 10 бюджетов кадра (400) —
ловит цепной взрыв v1.8.0 (тысячи за кадр), но не срабатывает на легитимных
значениях. Дополнительно три wall-clock тайминг-теста в
`test/perf.smoke.test.mts` получили `{ retry: 2 }` от node:test — транзиторный
провал под нагрузкой CPU (сборка, CI) проходит ретраем, детерминированный
провал падает после всех попыток. Пороги производительности не ослаблены.

## 5. Что требует ручной приёмки в черновике Яндекса

1. debug-панель (`?debug-mode=16`): индикатор лоадера `IT`.
2. Стартовая реклама платформы: звук молчит, меню не «живёт» под рекламой.
3. Interstitial при выходе в меню: после ошибки рекламы игра возвращается в меню ровно один раз.
4. Лидерборд: рекорд авторизованного игрока долетает до `highscore`.
5. Покупка `void_wraith` в черновике: владение восстанавливается после перезагрузки.
